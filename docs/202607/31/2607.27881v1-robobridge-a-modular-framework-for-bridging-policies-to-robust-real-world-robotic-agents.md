## 摘要
视觉-语言-动作（VLA）模型作为机器人操作的一种可扩展方法，已引起越来越多的关注。尽管这些模型是有效的动作预测器，但将它们部署为机器人智能体时暴露出关键差距：缺乏失败恢复机制、在长时间跨度内执行不一致、以及对观测、任务或实体变化的鲁棒性有限。现有解决方案通过模型重训练或环境特定模块来单独解决这些限制，但需要的是一个通用框架，能够系统地将预训练的VLA转化为机器人智能体。我们提出了RoboBRIDGE，一个模块化框架，它提供了五个协调模块上的编排层，即监视器（Monitor）、感知器（Perceptor）、规划器（Planner）、控制器（Controller）和机器人接口（Robot Interface），以从现成组件（包括预训练的VLA）组成稳健的机器人智能体。监视器将快速故障检测与分层恢复相结合，在错误级联之前纠正它们。当环境偏离当前计划时，规划器触发重新规划，同时感知器异步更新场景理解，避免执行停顿。在控制器内部，原始技能微调将操作分解为具有专用LoRA适配器的域不变原始技能，从而减少使用VLA时对域偏移的敏感性。在LIBERO、RoboCasa以及涵盖多个机器人平台和VLA主干的真实世界案例研究中，RoboBRIDGE始终优于独立策略和先前增强的VLA部署。这些结果表明，可靠的机器人智能并非仅来自扩展动作预测器，而是来自围绕它们的结构化编排。

## Abstract
Vision-Language-Action (VLA) models have attracted growing interest as a scalable approach to robotic manipulation. While these models are effective action predictors, deploying them as robotic agents exposes critical gaps: no mechanism for failure recovery, inconsistent execution over long horizons, and limited robustness to shifts in observations, tasks, or embodiments. Existing solutions address these limitations individually through model retraining or environment-specific modules, yet what is needed is a general framework that systematically transforms a pretrained VLA into a robotic agent. We present RoboBRIDGE, a modular framework that provides an orchestration layer over five coordinated modules, namely Monitor, Perceptor, Planner, Controller, and Robot Interface, to compose robust robotic agents from off-the-shelf components, including pretrained VLAs. The Monitor pairs rapid failure detection with hierarchical recovery to correct errors before they cascade. When the environment diverges from the current plan, the Planner triggers replanning while the Perceptor updates scene understanding asynchronously, avoiding execution stalls. Within the Controller, primitive skill fine-tuning factors manipulation into domain-invariant primitives with dedicated LoRA adapters, reducing sensitivity to domain shifts when a VLA is used. Across LIBERO, RoboCasa, and real-world case studies spanning multiple robot platforms and VLA backbones, RoboBRIDGE consistently outperforms both standalone policies and prior augmented VLA deployments. These results suggest that reliable robotic agency does not arise from scaling action predictors alone, but from structured orchestration around them.

### 2. 论文提出的方法论

**核心思想**：提出 RoboBRIDGE——一个模块化、与策略无关的编排框架，将任意动作生成策略（包括VLA）包装为稳健的机器人智能体，且无需重新训练或改动底层模型架构。

**框架结构**：由五个协调模块组成：

- **Monitor（监视器）**：闭环反馈，验证执行结果并在检测到失败时触发分层恢复。
- **Perceptor（感知器）**：将原始传感器观测转换为以物体为中心的状态（身份、3D位姿、语义属性如可供性和任务相关特性）。
- **Planner（规划器）**：接收精炼状态和语言指令，将任务分解为有序的原始技能序列，并附带上下文参数。
- **Controller（控制器）**：动作生成策略的插槽，将每个原始技能转化为底层动作。
- **Robot Interface（机器人接口）**：抽象具体机器人平台的API、时序、安全限制和坐标系变换，使同一上游逻辑可跨机器人运行。

**三大核心机制**：

**(a) 两阶段监控与故障恢复**

- **阶段一：轻量级成功检查** `Dcheck: (o_t, c_t) → (suc_t, con_t)`——周期性地用视觉语言模型评估当前观测与期望计划上下文的匹配度，使用约束输出格式抑制扩展推理，实现低延迟、不阻塞执行的持续检查。
- **阶段二：失败诊断与恢复**——当检测到失败且置信度足够时，调用诊断模型 `Ddiag: (o_t, c_t) → (r_t, reason_t)` 推断根因，并选择四个层级的分层恢复策略（按重计算范围递增）：
  1. **retry（重试）**：重新执行当前原始技能。
  2. **regenerate（重新生成）**：保留当前计划和感知状态，仅重新生成轨迹。
  3. **replan（重新规划）**：基于最新的异步感知结果重新规划。
  4. **re-perceive（重新感知）**：当物体状态被认为不可靠时，强制全面重新感知后再规划。

**(b) 基于异步感知的响应式规划**

- 采用**生产者-消费者架构**：感知线程通过线程安全缓冲区持续更新最新检测结果 `ō_t = Dpercept(o_t)`，隐藏感知延迟；执行线程在后台运行的感知结果之上顺序执行原始技能。
- **分歧触发的重新规划**：每个原始技能完成后，计算当前计划所用观测与缓冲区最新观测之间的分歧度：
  `Δ(ō_a, ō_b) = max_i∈O_a∩O_b [‖p(i)_a − p(i)_b‖₂] + λ·|O_a △ O_b|`
  其中 `p(i)` 为物体3D位置，`O` 为检测物体集合，`△` 为对称集差，`λ` 为物体出现/消失的权重。
- 当 `Δ ≥ τ` 时，保留高层动作序列（如 PICK → PLACE），仅用最新观测重新生成当前及后续动作的原始技能，避免冗余的高层推理。

**(c) 原始技能微调（Primitive Skill Fine-tuning）**

- 将操作分解为**域不变原始技能集合** `P = {MOVE, GRIP, ROTATE, ...}`，每个原始技能配备专用的**LoRA适配器** `Δθk`，附加在冻结的VLA主干 `fθ` 上：`fθ+Δθk: (i, s_t, p_t) → a(k)_t`。
- **控制器切换机制**：根据请求的原始技能选择对应适配器，若不存在则回退到所有已注册LoRA适配器的平均值。
- **动作生成与执行**：预测7自由度增量动作 `a_t = (δx, δϕ, g)`，以笛卡尔速度命令形式下发；若有IK求解器则转为绝对目标求解关节位置，IK失败时回退为速度命令，实现跨不同运动学接口的机器人适配。

**算法流程**（RunTask）：重置环境 → 初始感知 → 初始规划 → 启动异步感知线程 → 对每个原始技能循环执行：解析适配器 → 预测动作 → 环境交互 → 成功检查 → 若失败则停止并诊断恢复 → 技能完成后检查分歧度，超过阈值则重新规划。

### 6. 论文的主要结论与发现

- **框架整体有效性**：RoboBRIDGE在LIBERO上将平均成功率从35.5%提升到39.7%；在更具挑战性的RoboCasa上，三个骨干的平均成功率均获提升（SmolVLA：3.4%→6.9%；π0.5：3.4%→5.9%；GR00T-N1.5：4.2%→9.8%），排除Pick-and-Place任务后提升更显著（GR00T-N1.5从6.2%→14.7%）。
- **两阶段监控的必要性**：规划（Planner）质量单独不足以弥补VLA与可靠智能体之间的差距——无监控时各LLM骨干均处于1.8–8.0%狭窄区间；启用监控后显示明显分层，最强的Claude Opus 4.6达到14.7%（+8.1%），而小模型改善有限，说明有效的失败诊断需要足够的推理能力。
- **规划与监控缺一不可**：两者结合的效果随骨干诊断能力提升而放大。
- **框架对多种控制器的普适性**：LoRA微调+R-B达到27.1%，接近独立全量微调的31.9%（但参数少得多）；全量微调+R-B进一步达40.0%；经典IK控制器在框架内也达22.1%，验证了策略无关设计。
- **外部编排优于内部修正**：CycleVLA的模型内部子任务回溯和自纠正解码仅达7.5%，远低于RoboBRIDGE的外部编排效果，说明模型内部修正机制不足以替代结构化的外部编排。
- **主导失败模式**：(1) 感知错误——在杂乱场景中因遮挡或视觉相似物体导致目标错误识别或误定位；(2) 不可恢复的操作失败——接触密集交互中环境状态被不可逆改变，重试徒劳。

### 8. 不足与局限

- **实验覆盖的局限**：
  - LIBERO仅使用单个VLA骨干（GR00T-N1.5），未跨骨干验证框架在LIBERO上的泛化性。
  - RoboCasa上部分任务（尤其多数Pick-and-Place类）成功率仍为0%，框架对部分任务类别无能为力。
  - 表I和表II中若干任务在w/RB下反而低于基线（如LIBERO-Spatial的Task02、LIBERO-Goal的Task02等），论文未解释这类非一致下降。
- **失败修复能力的上限**：存在不可恢复的操作失败——接触密集交互中错误一旦造成不可逆环境改变，重试和重规划均无法补救；感知错误在严重遮挡或物体相似度高的场景中仍占主导。
- **手动设置的局限**：原始技能词汇表覆盖有限，无法处理接触密集交互、可变形物体和双臂任务；监控阈值和恢复规则目前是人工设定的，未从交互数据中学习。
- **信息缺失**：未披露计算资源细节（GPU型号和数量、训练时长）、未报告多次运行的标准差或置信区间、缺少泛化到新任务/新环境类型的系统性评估。
- **依赖LLM能力**：框架性能高度依赖作为Planner和Monitor的大语言模型的推理诊断能力，小模型下增益甚微，这引入对专有LLM服务（如Claude Opus 4.6）的外部依赖。
- **评估偏差风险**：真实世界评测结果以案例研究形式呈现，样本量有限，且视觉展示为主，缺少系统性的成功率统计比较。
