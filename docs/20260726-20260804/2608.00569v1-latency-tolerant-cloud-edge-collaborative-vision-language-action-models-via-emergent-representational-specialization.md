## 摘要
在移动机器人上部署十亿参数的视觉-语言-动作（VLA）策略会产生系统冲突：语义推理受益于云端GPU，而闭环控制必须在本地响应，尽管存在网络延迟和抖动。现有的层次化与异步策略提高了吞吐量，但其慢路径表示仍可能过期到达，或需要显式调度和延迟提示。我们提出CloudEdgeVLA，一种将时间错位视为表示学习问题的云边策略。云端VLA将延迟的观测编码为缓慢变化的任务特征，而轻量级边缘头将最新可用的云特征与当前本地视觉相结合。在训练期间，当前帧和随机延迟帧分别与相同的当前动作目标配对，形成新路径与过期路径。这一目标鼓励云端表示保留任务级信息，同时边缘路径提供状态敏感校正。在四个LIBERO基准套件中，CloudEdgeVLA在40步均匀延迟窗口内保持了63.8%至78.0%的成功率，而VLASH最高仅6.4%，评估的单路径基线最高仅3.0%。通过从控制回路中移除阻塞式同步，该设计为可扩展的VLA部署提供了一条实用路径，其中云模型可以不断增长，而边缘计算保持轻量且响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

  - 网络延迟、抖动（jitter）与丢包使得云端返回的特征描述的是过去时刻的场景，而非动作执行的当前场景。
- **现有方案的不足**：
  - 层次化/异步策略（如 MResT、DP-VLA、HiRT、SmolVLA、VLASH）虽然提高了吞吐量，但它们主要目标在于推理调度、动作块修正或显式时间条件化；其慢路径表示仍可能过期到达，且需要固定的频率比、有界延迟、显式调度或延迟提示。
  - 阻塞等待新特征会降低控制频率；不阻塞而用最新特征则引入时间错配（temporal mismatch）。
- **论文定位**：将时间错位（temporal misalignment）视为一个**表示学习问题**，而非纯推理调度问题，提出云边协同策略 **CloudEdgeVLA**，使云端模型规模可扩展、边缘计算保持轻量且响应迅速，从控制回路中移除阻塞式同步。

## 2. 论文提出的方法论

**核心思想**：借鉴 System 1/System 2 认知双系统隐喻，按时间角色分离信息：

- **云端 VLA 骨干（System 2，对延迟不敏感）**：编码"做什么"（任务目标、操作策略、物体语义）等缓慢变化的规划特征，而非"何时做"。
- **边缘视觉编码器（System 1 感知，对延迟敏感）**：从当前观测中提取实时视觉特征，提供无延迟的即时状态信号。
- **边缘动作头（System 1 控制，对延迟敏感）**：融合（可能过期的）云规划特征与实时视觉特征，输出连续动作，充当"实时接地层"。

**关键技术细节**：

- **系统性架构**：
  - 云端骨干：`h = fθ(o, ℓ) ∈ R^{L×D}`，基于预训练 VLM 的 LoRA 适配，仅在云端运行；L = T × A（动作块长度 × 动作维度）。
  - 边缘视觉编码器：`zt = vψ(ot) ∈ R^{Dv}`，使用冻结的 SigLIP-Base。
  - 边缘动作头：`â_t = gϕ(h_{t-k}, z_t) ∈ R^{T×A}`，先对规划特征按动作维度做均值池化，将视觉特征投影到同一潜在空间，拼接后经残差 MLP 预测动作块。

- **成对帧双路径训练（Paired-Frame Dual-Path Training）**：
  - 从同一幕（episode）中提取 W 个连续观测的窗口，构造当前帧 ot 与延迟帧 ot−d（d ~ Uniform(1, W−1)）。
  - 两帧分别过云端骨干得到 h_fresh 和 h_stale，各自与相同的实时视觉特征 zt 融合，预测同一真实动作 at，构成双路径损失：
    - L = (1−λ)·L_fresh + λ·L_stale，两者均为 L1 损失。
  - 采用课程学习（curriculum learning）：λ 从 0 逐步增加到 λ_max，先让骨干学习强表示，再迫使其对延迟不敏感。
  - h_stale 不脱离计算图，两条路径均参与梯度回传。

- **部署协议**：完全异步、非阻塞：
  1. 边缘采集 ot 并发送至云端；
  2. 云端返回特征时，边缘直接更新 h_received（可能来自旧的 ot−k）；
  3. 边缘本地计算当前视觉特征 zt；
  4. 边缘计算 ât = gϕ(h_received, zt) 并执行。
  - 机器人永不等待云端响应，始终用最新可得的云特征 + 当前实时视觉。

- **涌现式表征特化机制**：跨随机延迟 d，仅与瞬时状态绑定的特征对预测 at 不可靠，而任务身份、目标、粗略进度等信息更稳定，从而鼓励云端特征对时间位移不敏感；当前边缘特征保留状态敏感信息。

## 3. 实验设计

**基准（Benchmark）**：

- **LIBERO 操作基准**（Liu et al., 2023）：4 个任务套件（Spatial、Object、Goal、Long），每套 10 个任务，每任务 50 个演示幕，用于评估语言条件下的仿真操作。

**对比方法（Baselines）**：

- 单路径策略：OpenVLA、OpenVLA-OFT、UniVLA（将延迟帧直接输入其原始推理路径）。
- 异步策略：VLASH（未来状态感知异步推理，在相同的均匀延迟网格上评估）。

**评估条件**：

- 无延迟（dmax=0）：同步参考。
- 均匀延迟（k ~ Uniform{1, ..., dmax}），dmax ∈ {5, 10, 15, 20, 25, 30, 40} 步。
- 每个任务 50 次试验，报告成功率；CloudEdgeVLA 使用 3 个随机种子（7、8、9）报告均值±标准差。

**消融实验**：

- 视觉编码器贡献：无视觉编码器 vs SigLIP-Base vs SigLIP-SO400M。
- 损失路径贡献：仅 L_fresh、仅 L_stale、联合 L_fresh + L_stale。

**真实机器人实验**：

- Franka 拾放试点：RTX 5080 工作站跑边缘组件和控制器，RTX 4090 服务云端 7B 骨干。
- 任务：把玩具熊放入盒子；静态与动态（目标移动 10cm）两种设置；额外 RTT 为 0/400/1000 ms；每种方法每设置 10 次试验。

**机制诊断（离线诊断）**：

- 在 LIBERO-Spatial 的 10 个任务各取 1 个演示幕、每幕 8 个有效时间步，共 80 个共享评估状态；对比 OpenVLA-OFT 与对齐后的 CloudEdgeVLA（120k 步）在确定性偏移 d∈{0,1,3,5,8,10,15,20} 下的骨干漂移 Dh、端到端动作漂移 Da、转移增益 κ = Da/(Dh+ε)、演示 MAE 等指标。
- 反事实审计：独立变化云端骨干延迟 dh 与边缘观测延迟 dz，检验边缘视觉对过期云特征的直接校正能力。

## 6. 论文的主要结论与发现

- 在主实验（LIBERO 四套件）中：
  - dmax=10 时：OpenVLA 成功率最高仅 6.8%，OpenVLA-OFT 最高 26.2%，UniVLA 在 Goal 套件保留 48.2%，VLASH 最高 62.8%，CloudEdgeVLA 保持 83.2%–94.4%。
  - dmax=40 时：CloudEdgeVLA 保持 63.8%–78.0% 成功率（各套件分别下降 18.5–27.9 个百分点），VLASH 最高 6.4%，单路径基线最高 3.0%。
  - 四套件宏平均曲线：CloudEdgeVLA 归一化延迟 AUC 为 90.8%（VLASH 为 32.4%）；保留同步成功的 76.5%（VLASH 仅 1.8%）。
- 消融结果表明：
  - 实时视觉接地（SigLIP-Base）带来 63.5 个百分点的增益（31.6%→95.1%），远超编码器规模的影响（换 SO400M 仅 +0.7 点），支持边缘采用轻量编码器。
  - 仅 stale-only 训练达到 89.2%，比 fresh-only 高 34.4 点，说明显式延迟暴露驱动主要鲁棒性；联合训练再加 5.9 点，fresh 路径提供互补接地。
- 机制分析：
  - 在 d=20 时，CloudEdgeVLA 将骨干表征漂移降低 59.2%（Dh: 0.391→0.160），将动作漂移转移增益降低 72.7%（κ: 1.082→0.295），组合效应使动作漂移降低 88.9%（0.423→0.047），演示 MAE 降低 88.5%（0.421→0.048）。
  - 反事实审计显示：在 120k 步检查点上，直接由边缘视觉校正过期云特征的效果很弱（rescue 比例 0.03%），鲁棒性主要来自稳定骨干 + 衰减残余漂移的动作头——这一负结果恰当地约束了机制主张，不削弱端到端观测到的鲁棒性。
- 真实机器人试点：1000 ms RTT 下 VLASH 降至 0/0%，CloudEdgeVLA 保持 80/70%（静态/动态）。

## 7. 优点

- **问题建模视角新颖**：将延迟鲁棒性视为"学习到的接口属性"，而非纯推理调度问题；云边接口传输的是可复用的任务特征而非时间索引的动作计划。
- **架构设计简洁而巧妙**：
  - 非阻塞、无时钟/频率对齐要求的部署协议，实际落地友好。
  - 边缘闭环视觉反馈在每一步都闭合，不像动作块重放那样假设环境静止。
  - 云端骨干可独立扩展规模，边缘计算保持轻量。
- **训练方法有效且优雅**：同一动作目标监督当前帧和随机延迟帧，自然地将信息按时间角色分离，无需显式不变性损失或延迟元数据。
- **实验层次丰富且诚实**：主实验、消融、真实机器人可行性验证、机制诊断、反事实审计层层递进；作者主动披露了机制的局限性（边缘直接校正能力弱），提升了研究的可信度。
- **分析深度突出**：不仅报告任务成功率，还从表征漂移、动作漂移、转移增益、逐任务一致性、动作块分解、反事实年龄等维度解剖方法的工作机制。

## 8. 不足与局限

- **延迟分布覆盖有限**：仅测试了均匀延迟窗口（最大 40 步），对更极端分布（长尾延迟、断连）的鲁棒性未知；作者明确指出"不意味着无界延迟或云端断连的容忍度"。
- **训练成本增加**：成对帧双路径训练每次更新需要两次骨干前向传播，训练开销高于单路径方法，论文未量化额外成本。
- **感知模态受限**：冻结的 RGB 编码器可能丢失深度、力/触觉或接触信息，限制了需要精细力控的任务。
- **真实机器人验证薄弱**：仅在单一平台（工作站级边缘设备）上做了小样本试点（每单元格 10 次），非嵌入式硬件，不能证明边缘计算效率或广泛硬件泛化性。
- **机制测试的统计功效有限**：离线诊断基于 80 个共享状态，对比检查点在架构和目标上均不同，无法完全归因于单一组件。
- **基线比较不完全对等**：主表中基线为单次点估计、无方差，统计公平性不足；不同方法的延迟处理方式本身存在本质差异，严格的"受控比较"难以完全保证。
- **部署层面的未解决问题**：对于断连处理，作者明确建议需要时间戳特征和本地回退策略，但本文未实现这些机制。
